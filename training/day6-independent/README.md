## Day 6 TODO（唯一任务）：给工具调用加“连续失败不超过 2 次”的容错

背景：Day 2 学会了“把工具错误喂回模型”，但没有限制重试次数——如果工具持续失败、
模型又反复请求它，就会一直烧 token（Day 4 你也见过死循环的变体）。

在 [agent.py](agent.py) 的 `run_agent` 里实现：

1. 统计每个工具的**连续失败次数**，要**跨轮累计**；
2. 同一工具已连续失败满 2 次后，后续对它的调用**不再真正执行** `execute_tool`，
   直接构造一条以 `[工具错误]` 开头、说明“已重试 2 次，放弃重试”的结果；
3. 放弃时也要用 `build_tool_result` 回填 `role="tool"` 消息，`tool_call_id` 不能丢；
4. 该工具**成功执行一次**要把它的失败计数清零（想清楚“连续”的定义）；
5. 其他路径不变：日期问题正常、未知工具仍抛 `ValueError`、不联网也能跑。

> 注意：现有的 `_mock_llm` 看到 `[工具错误]` 就会收尾，不会触发“连续失败”。
> 所以测试需要你自己构造一个“反复请求同一个工具”的假 `llm`——这也是本次要考的测试设计能力。

## 测试要求（至少新增两个用例）

1. 连续失败满 2 次后进入“放弃重试”：断言恰好真正执行了 2 次，之后是放弃消息；
2. 覆盖“成功清零”或另一个你设计出来的边界（例如失败 1 次后成功，再失败仍会真正执行）；
3. 断言行为契约（消息的 role / tool_call_id / 内容前缀 / 次数），而不是实现细节；
4. 全部离线、确定性、不需要 API Key。
