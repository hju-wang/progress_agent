## 三个 TODO（细节都写在代码注释里）

### TODO-1（向量化）

把 token 列表编码成 `{token: 权重}`：统计 tf，乘以 `idf[token]`，
资料库里没见过的 token 跳过。**这里故意不做归一化**——归一化是 TODO-2 分母的职责，
分开写，将来拿未归一化的向量去调余弦函数也不会算错。

### TODO-2（相似度）

`点积 / (|a| × |b|)`。注意三点：分子只累加**共有** token；
分母是各自的 L2 范数；任一向量为空或范数为 0 时返回 `0.0`（别让它除零崩掉）。

### TODO-3（检索与 0 命中）

查询编码 → 与每个块算余弦 → 降序排序（**同分按 chunk id 升序**，保证结果可复现）
→ 丢掉低于 `min_score` 的 → 取前 k 个 → 一个不剩就返回**空列表**。

`min_score` 是防幻觉的第一道闸门：没有它，任何问题都能撞到一条低分资料，
模型就会拿不相关的材料编答案。

## 对比实验说明：`evaluate.py`

它用同一批文档、同一个切词，把 Day 3 的关键词计数和你的向量检索并排跑：

| | 命中率@1 | 命中率@3 | MRR |
| --- | --- | --- | --- |
| 关键词计数（Day 3） | 80% | 100% | 0.900 |
| TF-IDF 向量（Day 9） | 100% | 100% | 1.000 |

差距来自用例 5（`分块太大有什么坏处？`）：三个块都只共用一个 token、都算 1 分，
关键词计数**给不出区分度**，只能按 id 兜底，于是最长的 `doc-2-1` 意外排第一；
余弦相似度把长度除掉之后，短而主题集中的 `doc-5-1` 才回到第一。

**这个结果要诚实地读**：小语料上，差距来自"打平怎么处理"和"长度偏置"这两件工程上的事，
**不是**"向量比关键词更懂语义"。`evaluate.py` 里的换述用例（`怎么防止模型胡说八道？`）
两种检索都没命中，就是证据——稀疏词频向量词不重叠就近似正交。

## 消融实验（教练实测，复述题 1、2 的证据都在这里）

一次只动一处，就能看出每块积木各自贡献了什么：

| 版本 | 命中率@1 | MRR |
| --- | --- | --- |
| 关键词基线（Day 3） | 80% | 0.900 |
| 完整实现（tf × idf + 余弦归一化） | 100% | 1.000 |
| 去掉归一化（只留点积） | 80% | 0.900 |
| idf 全设成 1（只留 tf + 归一化） | 100% | 1.000 |

怎么读这张表：

- **真正在起作用的那一步是归一化。** 去掉它之后，用例 4（`怎么评测检索效果？`）的第一名
  从正确的 `doc-6-1`（13.4）变成又长又泛的 `doc-2-1`（15.7）：长块靠 token 数量把分数堆上去，
  命中率@1 从 100% 掉回 80%，跟关键词基线一样。这就是"长度偏置"，也正是 Day 3 那版打分的老毛病。
- **idf 在这个小语料上几乎没有贡献**：全部设成 1 之后，五个用例的排序和指标都没变。
  6 篇文档、词表太小，df 之间的差距拉不开。想看 idf 的威力，得专门造一个"高频词刷分"的用例
  （问句里有个到处都出现的词，而某条不相关的块只靠这个词得分）——留给 Day 10 做 eval 时补。
- **用例 5 的差异来自"打平怎么处理"，不是归一化**：去掉归一化它照样命中（`doc-5-2` 排第一）。
  所以复述第 1 题只盯着用例 5 看，会得出"没区别"的结论——这个坑已经踩过一次了。

## 诚实说明：这不是神经 embedding

今天实现的向量是**稀疏词频向量（TF-IDF）**，不是神经网络 embedding。
两者共享同一套工程骨架（编码器 → 向量 → 索引 → 相似度 → top-k），
**差别只在编码器**：神经 embedding 能把同义词、换述映射到相近位置，稀疏向量做不到。

之所以先在本地用 TF-IDF 练：一是离线、零依赖、可复现（本项目所有测试都不联网、不要 API Key），
二是把骨架里的每一步都握在自己手里；之后要换成神经 embedding 服务（外部模型），
替换的只是 `embed()` 这一个函数——接口已经为这件事留好了。

## 复述（代码任务完成后在对话里回答，合上代码）

1. 余弦相似度为什么要除以两个向量的长度？如果不除，在这 6 篇文档上会出现什么现象？
   （提示：别只看用例 5——实测去掉归一化后用例 5 仍然命中，真正被长块反超的是用例 4，见下方「消融实验」）
   答：如果不除两个向量的长度的话，即便是两个完全一样的向量，也会算出来相似度大于1 ，这样是不符合要求的，这就是没有做归一化，相似度应该是在 0-1 之间的一个数字
2. `idf` 到底在干什么？如果把所有 token 的 idf 都设成 1（等于只用 tf 不加权），
   哪些用例的排序会变差？为什么？（实测方法见下方「消融实验」：把 `compute_idf` 的返回值改成 `{token: 1.0 for token in df}`，重跑 `evaluate.py` 对比）
   答：idf 的意思是逆文档频率，意思就是看这个token 是大众化的词，还是在某个文档中出现频繁，而在其他文档中出现不频繁的词
3. 稀疏 TF-IDF 向量和神经 embedding 的区别在哪、各自在什么场景下会赢？
   举一个本实验里两边都失败、但神经 embedding（外部模型）可能成功的例子。
   
   答案：举例子question="怎么防止模型胡说八道？",这个question 如果按照稀疏向量的方式拆分，无论如何分词，都分不出和文档相关的词汇，神经embedding 有判断近义词的功能

## 常见坑

- `idf.get(token)` 忘了判空 → `KeyError`；
- 忘了除范数 → 长块靠体积反超：实测去掉归一化后，用例 4 的第一名从 `doc-6-1` 变成 `doc-2-1`（15.7 vs 13.4），整体命中率@1 从 100% 掉回 80%；
- `min_score` 设太高（比如 0.5）→ 全部 0 命中；
- 排序时没加"同分按 id"的兜底 → 结果随机，测试时红时绿。
