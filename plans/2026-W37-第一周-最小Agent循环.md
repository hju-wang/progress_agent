> **重要修订（2026-09-08）**：经与用户确认，此前的代码经历基本是“复制粘贴 + AI 代写”，

## 三条总规则（防自欺）

1. **AI 边界**：白天可以请 AI 讲原理、review、改 bug；但“亲手写”任务（每天标注 🔧）要求自己写代码。AI 帮你写的每一段，都要能自己复述。
2. **完成定义**：每天结束时必须能回答三个问题——它能运行吗？你能讲清为什么这么写吗？不靠 AI 你能改它吗？三个都“能”才算过。
3. **时间盒**：单日 4 小时封顶。没做完就砍“探索性内容”，**不许砍验收**；宁可少做，不能又陷入“学不完干脆不学”。

## Day 1（9/8 周三）：接上 DeepSeek，先拿到“可信的结构化输出”

- 学习（45m）：DeepSeek API 文档（OpenAI 兼容）；搞懂 chat completion 的 messages 结构；JSON/结构化输出的正确姿势。
- 🔧 动手（2h）：`uv init mini-agent` 并加 `openai`（或 `httpx`）依赖；写 `llm.py`：输入问题 → 返回结构化 JSON（比如 `{"answer": ..., "confidence": ...}`），用类型标注定义返回模型。
- 收尾（45m）：写一个最小 CLI `python -m mini_agent ask "..."`；整理 `.env.example`。
- 独立检查（30m，可查文档、不写代码时禁问 AI 怎么写）：手动把返回里的非法 JSON 场景处理掉（解析失败怎么办？）。

验收：CLI 能稳定输出 JSON；你能讲清 messages、temperature、response_format 各是什么。

## Day 2（9/9 周四）：Function Calling——让模型学会“叫人干活”

- 学习（45m）：function calling 的协议：tools 参数、tool_calls、工具返回结果的 role。
- 🔧 动手（2h）：在 `tools.py` 里定义 3 个真实工具（如 `get_current_time`、`add_numbers`、`read_file`），写“调用模型 → 拿到 tool_calls → 执行 → 把结果塞回对话 → 再调模型”的循环（一次工具调用即可）。
- 收尾（45m）：给工具加输入校验；拒绝执行会改系统状态的工具。
- 独立检查（30m）：故意写一个工具 schema 错误，不靠 AI 修复并解释原因。

验收：Agent 能回答“现在几点 + 127+58=？”这类必须调用工具的问题。

## Day 3（9/10 周五）：亲手写 ReAct 主循环

- 学习（45m）：ReAct 思想（Thought / Action / Observation）；为什么需要 max_iterations 和终止条件。
- 🔧 动手（2h）：实现 `agent.py`：循环内“让模型思考 → 选工具 → 执行 → 观察”，支持连续多次工具调用；无工具可调或超过轮数时停止并返回。
- 收尾（45m）：加日志：每轮打印 `[thought] [action] [observation]`，肉眼可跟。
- 独立检查（30m）：不靠 AI 把“最大轮数=3”改成可配置，并说明为什么这个参数重要。

验收：它能自己规划“先查时间、再算加法”这类两步任务；日志清晰。

## Day 4（9/11 周六）：让它不崩——错误恢复与测试

- 学习（45m）：工具调用常见的失败模式：JSON 解析失败、工具抛异常、模型乱填参数、超时、重复执行。
- 🔧 动手（2h）：`agent.py` 加错误恢复：工具失败 → 把错误文本喂回模型让它修正；非法输出 → 重试（限次）；超时 → 降级回答。
- 收尾（1h）：写 pytest：**用 fake LLM** 模拟“第一次返回非法 JSON、第二次正常”等场景，断言 Agent 最终成功或优雅失败。
- 独立检查（30m）：给代码补一个你自己发现的边界测试。

验收：`uv run pytest` 至少 3 个用例通过；你能讲清“为什么不能让 Agent 无限重试”。

## Day 5（9/12 周日）：把 RAG 接回你的工具箱

- 学习（45m）：回顾 rag-demo 的分块/检索思路；明确“RAG 在 Agent 里就是一个检索工具”。
- 🔧 动手（2h）：给 mini-agent 加“本地文档工具”：读 2-3 个 `.md` → 分块 → 用 Embedding API 转向量存内存 → 查 top-3 → 把片段作为工具结果返回。
- 收尾（45m）：要求回答带引用（回答里注明出自哪个文件），输出记录到日志。
- 独立检查（30m）：问一个文档外的问题，验证 Agent 会回答“不知道/没找到”，而不是编造。

验收：Agent 能基于你放的文档回答问题，并标注来源；不会的问题不乱编。

## Day 6（9/13 周一）：看一眼“正规军”——LangGraph 跑同一件事

- 学习（45m）：LangGraph 的核心概念：State、Node、Edge、条件边；和手写循环对照。
- 🔧 动手（2h）：`uv add langgraph langchain-openai`；用 LangGraph 实现同样的“思考 → 调工具 → 再思考”流程（至少能跑通 Day 2 的任务）。
- 收尾（1h）：写一页 `docs/why-langgraph.md`：手写 vs 框架，各解决了什么、藏了什么坑。
- 独立检查（30m）：不靠 AI 解释：LangGraph 里“循环”是用什么机制表达的？

验收：同一任务在手写版和 LangGraph 版都能跑通；你能说出两者差异。

## Day 7（9/14 周二）：独立检验日——不靠 AI 过一天

- 上午任务（2h，**全程禁问 AI 写代码**，可查文档）：给 mini-agent 增加一个新工具 `count_words_in_file`（或等价功能），要求：有 schema、有校验、有测试、Agent 能调用并汇报结果。
- 复盘（1h）：跑 `cd app && PYTHONPATH=src python3 -m progress_agent assess`，再次自测；再跑 `gap` 命令对比本周变化。
- 周记（30m）：写 `data/weekly/2026-W37.md`：本周做了什么、卡在哪、哪些能力从“我以为会”变成“我真的会”。
- 下周预告（30m）：看一个你保留的目标 JD（如密尔克卫 003），划出它要求而你本周没碰的技术点，作为下周选题。

验收：独立任务完成且测试通过；自测报告中 A2/A4/B1/B2/E4 至少有 2-3 项从 0→2；你能用 3 分钟向别人讲清 mini-agent 的架构。
