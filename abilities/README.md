# abilities —— 能力模型资产

这里是系统的“能力地图”，回答一个核心问题：**Agent 应用开发工程师的岗位到底要求什么、怎么检测**。

## 当前版本

- `agent-app-developer.v0.1.json`：Agent 应用开发工程师能力模型 v0.1（草稿）。
- 角色聚焦：**Agent 应用开发**。

## 能力模型结构

模型按“维度 → 能力项”组织，共 6 大维度、31 个能力项：

| 维度 | 定位 |
| --- | --- |
| A. 大模型基础与应用 | LLM 能力边界、提示、上下文、Function Calling、RAG |
| B. Agent 核心与编排 | Agent 循环、框架运用、多 Agent、状态、人机协同 |
| C. 工具与生态 | MCP、工具设计、记忆、系统集成、沙箱安全 |
| D. 评测与质量 | Eval、自动评测、可观测、Guardrail、成本优化 |
| E. Python 工程能力（硬门槛） | 语言、async、FastAPI、测试、工程化、独立调试 |
| F. 求职交付 | 项目叙事、系统设计表达、JD 对齐、面试应对 |

每个能力项包含检测方式（`knowledge_q` 知识问答 / `practical_task` 实操任务 / `interview` 面试问答 / `code_review` 代码审查），具体题目与评分卷由检测引擎另行维护。

## 掌握度档位（全局评分用）

| 档位 | 含义 |
| --- | --- |
| 0 未知 | 没接触过，说不清是什么 |
| 1 概念 | 能说出是什么、有什么用 |
| 2 照做 | 有参考/教程时能实现 |
| 3 独立 | 限时、少 AI 辅助也能独立完成并解释设计 |
| 4 调优 | 理解权衡，能按场景调优并讲清楚为什么 |

注意：由于用户现有项目含较多 AI 生成内容，检测时**必须控制 AI 辅助程度**，档位判定以“独立完成”为可信证据。

## 版本与变更规则

- 能力模型属于“L1 内容资产”，任何增删改都必须走提案 → 测试 → **用户批准** → 合入流程。
- 文件命名带版本号，如 `*-v0.1.json`、`*-v0.2.json`；历史版本不覆盖。
- 权重不写死在模型里：每个 JD / 岗位画像会动态计算各能力项的权重。
