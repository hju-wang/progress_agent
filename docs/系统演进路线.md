# ProgressAgent 系统演进路线 v0.1

## 问题：为什么不能永远靠“聊天 + 改代码”

聊天模式擅长的是判断（观察卡点、批改、调计划），但把 NEXT 更新、成绩记录、试卷批改、commit 等簿记工作也人肉做，会有三个问题：

1. 换对话就“断片”，状态靠文件手工同步；
2. 每天花大量时间维护系统文件，挤占真正的训练时间；
3. 进入攻坚模式（JD → 出卷 → gate → 复测）后，流程变长，聊天会失控。

## 分工原则

- **AI 留作判断者**：决定提示力度、批改标准、计划取舍、是否放行。
- **系统负责执行者**：状态流转、试卷呈现与存档、成绩计算、周报草稿、NEXT 更新。
- 训练时间优先：每天 4 小时大头用于做任务和考试；系统功能只在复盘日演进，禁止吞噬训练时间。

## 三层路线

### 第 1 层：聊天辅导 + 文件记录（当前，W37）

- 目标：打通“最小 Agent 闭环”，验证能力模型 + 具体试卷 + 差距报告是否真实有效。
- 纪律：功能冻结，只做小修补；每天完成 → 总结进当天 README → 更新 NEXT。

### 第 2 层：簿记自动化（建议 Day 7 复盘后启动）

- `exam` 子命令：读 `assessments/papers/*.json` → 出卷 → 自动存档考生答案；客观题自动判分，主观/代码题生成“待教练批改”清单。
- 批改后：成绩写回能力档位 → 重跑 gap → 自动更新 NEXT。
- 每周复盘命令：`weekly-checkpoint` 产出周总结草稿 + 下一周计划建议。

### 第 3 层：求职教练 Agent（进入攻坚模式时）

- 用户甩来目标 JD → 拆解 → 生成对岗试卷 → 设定 100 分准入线 → 多次 gate 测试 → 连续达标才绿灯。
- 聊天只是前端；题库、成绩、状态全部在系统里，任何新对话都能续接。

## 层间切换判据

- 第 1 → 2 层：Day 6 独立检验通过 + 周复盘确认“检测与计划流程有效”。
- 第 2 → 3 层：用户拿到第一个意向 JD 并进入攻坚模式。
- 反向触发：连续两周无实质提升 → 停止自动化推进，先做真实水平与方向复盘。
