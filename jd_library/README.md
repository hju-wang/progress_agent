# jd_library —— JD 与岗位画像资产

这里是系统的“市场雷达”：存放从网络上采集的真实岗位 JD，并沉淀为岗位画像。

## 入库策略（v0.5 决策）

- 不直接“爬”招聘网站；采用 **搜索引擎 / 公开网页 + 真实 JD 种子** 的半自动采集。
- 新 JD 先进入 `candidates/`，状态为 `candidate`（候选）。
- **每个 JD 入库前必须经用户确认**（这是“任何合入都需用户知情”的一部分）。
- 确认后进入 `approved/` 并生成/更新岗位画像；过期或失效后标记为 `stale`。

## 目录结构

```
jd_library/
├── README.md
├── candidates/    # 候选 / 已弃用 JD
├── approved/      # 已确认入库的 JD
└── profiles/      # 聚合后的岗位画像
```

## 文件格式

每个 JD 一个 Markdown 文件，front-matter 含：id、标题、公司、地点、薪资、经验、来源、抓取日期、状态。
正文保存职责与要求的原文要点；文末附“能力标签（初步解析，待校准）”与备注。

## 采集渠道实测记录（2026-09-08）

- **猎聘 / 前程无忧（quanzhi 转链）**：可公开访问，能抓到完整 JD 正文，当前主力来源。
- **Boss 直聘**：网页端与接口均需 JS 验证/登录，工具直接访问返回“加载中 / 请稍候”，搜索引擎仅能拿到少量索引页片段，**当前无法作为自动采集来源**。后续若引入真实浏览器自动化或由用户手动提供链接，再评估接入。
- 腾讯招聘等单页应用：正文需 JS 渲染，暂不作为自动来源；可通过搜索引擎片段发现线索后人工补全。
