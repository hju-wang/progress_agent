# Agent 应用开发工程师 岗位画像 v0.1

- 快照日期：2026-09-08
- 样本：4 份已确认入库的真实 JD（jd-2026-0908-001 ~ 004）
- 样本来源：上海、成都、杭州（一线/新一线城市居多）

## 样本概览

| JD | 公司/场景 | 薪资 | 经验 | 技术重点 |
| --- | --- | --- | --- | --- |
| 001 | 上海喜啦 / ToB AI 陪伴机器人 | 15-25K | 2 年+ | Agent+Workflow、Function Call、MCP、企业级 RAG |
| 002 | 成都大能 / 嵌入式研发场景 Coding Agent | 15-25K·13薪 | 1-3 年 | MCP Server、LangGraph、代码知识库、IDE 集成 |

| 004 | 杭州碳路 / 企业级多 Agent | 15-30K·13薪 | 2 年+ | 单/多 Agent、ReAct/Plan&Execute、记忆、RAG、业务系统集成 |

薪资带集中在 15K–30K，要求 1–3 年或 2 年以上 AI 应用/后端经验，均为本科起步。

## 能力需求频率（n=4）

| 能力标签 | 出现 | 说明 |
| --- | --- | --- |
| Python | 4/4 | 全体硬性要求，无一例外 |
| LLM 应用开发 / Agent 系统落地 | 4/4 | 岗位存在的前提 |
| 工具调用（Function / Tool Calling） | 4/4 | 与 Agent 落地强绑定 |
| RAG（检索增强） | 4/4 | 均要求 RAG 或知识库能力 |
| 主流 Agent 框架（LangChain/LangGraph/AutoGen 等） | 4/4 | 至少一种且“有实际落地经验” |
| 后端 / API / 服务工程 | 4/4 | Web 框架、接口、部署能力 |
| 业务系统 / 多系统集成编排 | 4/4 | 对接内部系统、数据源或业务链路 |
| 上下文 / 记忆 / 状态管理 | 4/4 | 形式不同：上下文管理、多轮执行、记忆、状态 |
| MCP / MCP Server | 3/4 | 出现率高且越来越主流 |
| 向量数据库 | 3/4 | Milvus / Chroma / FAISS 等 |
| 效果评测 / 稳定性 / 成本优化 | 2/4 | 明确写出的是进阶岗位，但面试常追问 |
| 多 Agent / 多智能体协作 | 2/4 | 或明确要求，或作为“跟进方向” |
| 部署 / Docker / Linux | 2/4 | 多为加分或隐含要求 |
| Coding Agent / 沙箱 / IDE 集成 | 1/4 | 细分方向，样本里仅大能明确要求 |

## 对训练权重的初步指导

**Tier 1（必练，出卷权重最高）**
Python 工程能力、Agent 运行循环与工具调用、RAG、主流 Agent 框架落地、API/服务工程。

**Tier 2（高频，常以追问出现）**
MCP、上下文/记忆/状态管理、工作流编排、系统集成、评测与可观测。

**Tier 3（进阶/加分，拉开差距）**
多 Agent 协作、沙箱与安全、成本/延迟优化、部署运维、细分场景（如 Coding Agent、IM 机器人）。

## 使用注意

- 本画像仅代表当前 4 份样本；每 2–4 周应增量刷新，过期 JD 降权。
- 具体出卷权重由“攻坚模式”针对用户提供的目标 JD 动态计算，本画像只作巡航模式的基准。
